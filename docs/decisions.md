# Журнал решений

Здесь фиксируются решения, влияющие на тему, методику или архитектуру.

## 2026-11-19 — Постановка КТ1 принята как исходная точка

- **Решение:** цель, объект, предмет, гипотеза, архитектура и схема эксперимента
  перенесены из презентации КТ1 в исследовательские документы репозитория.
- **Причина:** сохранить согласованную исходную постановку и связать её с
  реализацией.
- **Статус:** подтверждена как версия КТ1, требует актуализации.

## 2026-11-19 — Роль реальных инцидентов требует согласования

- **Решение:** пока не объединять автоматически исследовательское тестирование
  с преобразованием текста реального инцидента в формальный сценарий.
- **Причина:** эти постановки требуют разных baseline, метрик и роли агента.
- **Статус:** предложено, требуется решение научного руководителя.

## 2026-11-19 — Анализ инцидентов предшествует реализации стенда

- **Решение:** сначала получить из корпуса инцидентов три связанных блока:
  каталог узлов, каталог операций и матрицу требований. Модель данных, Bank API
  и смарт-контракты проектировать после ревью этого результата руководителем.
- **Причина:** именно такой порядок прямо задан на встрече 2026-11-12; он
  обеспечивает трассируемость архитектуры и контрольных правил до реальных
  инцидентов.
- **Статус:** подтверждено руководителем как ближайший порядок работы; роль
  текстов инцидентов внутри финального агентного эксперимента всё ещё требует
  отдельного согласования.
