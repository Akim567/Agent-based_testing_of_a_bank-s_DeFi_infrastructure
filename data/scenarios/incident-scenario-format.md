# Формат сценария инцидента

**Статус:** черновой формат для пилотных сценариев  
**Версия:** `0.1`

Файл описывает воспроизводимый сценарий, полученный из реального инцидента.
Первая версия использует YAML, но сохраняет только структуры, которые без
изменений представляются в JSON.

## Основные разделы

| Раздел | Назначение |
| --- | --- |
| `metadata` | Идентификатор, название, версия формата и статус проверки |
| `source` | Исходный инцидент, ссылка и зафиксированная версия источника |
| `mapping` | Класс ошибки и требования, полученные из инцидента |
| `initial_state` | Участники, счета, разрешения и начальные балансы стенда |
| `configuration` | Включённые или отключённые проверки стенда |
| `actions` | Последовательность команд, выполняемых участниками |
| `oracle` | Инварианты и наблюдаемые признаки нарушения |
| `expected_result` | Ожидаемый итог на уязвимой и защищённой конфигурации |

## Минимальный контракт

- Сценарий должен иметь уникальный `metadata.id`.
- Каждое действие получает стабильный `step` и использует логическую команду
  Bank API.
- Все ссылки на участников, счета и операции должны разрешаться внутри файла.
- `oracle.requirements` содержит идентификаторы из матрицы требований.
- Уязвимый и защищённый прогоны используют одинаковые действия и отличаются
  только конфигурацией проверок.
- Успешным считается сценарий, который воспроизводит нарушение на уязвимой
  конфигурации и блокируется на защищённой.

## Статусы

- `draft` — сценарий сформирован, но не проверен вручную;
- `reviewed` — шаги сверены с источником;
- `reference` — сценарий стабильно воспроизводится и используется в эксперименте.

Шаблон находится в [`incident-scenario-template.yaml`](incident-scenario-template.yaml),
а заполненный пилотный пример — в
[`orderfactory-unauthorized-order.yaml`](orderfactory-unauthorized-order.yaml).
